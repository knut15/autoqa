# TC 작성 가이드

autoqa 는 여러분이 이미 쓰고 있는 QA 문서를 그대로 읽는다. **문서를 새로 쓸 필요는 없다.** 칸 두 개만 더하면 자동으로 돌아간다.

## 1. 시작하는 법

리포 루트에 `.autoqa.json` 하나를 둔다.

```json
{
  "project": "우리 서비스",
  "sources": [{ "adapter": "markdown", "file": "docs/qa/cases.md" }],
  "app": { "start": "pnpm dev", "baseUrl": "http://localhost:3000" }
}
```

이것만으로 TC 목록이 화면에 뜬다. 아직 아무것도 자동 실행되지 않는다 — 다음 단계가 그것이다.

## 2. 표에 칸 두 개를 더한다

```
| ID | P | 사전조건 | 절차 | 실행 | 판정 | 기대 결과 |
```

`실행` 은 기계가 무엇을 하는지, `판정` 은 무엇을 보면 통과인지다. **비워두면 그 TC 는 자동 실행되지 않는다.** 되는 것부터 채우면 된다.

## 3. 실행 칸 — 네 가지 중 하나

### 셸 명령

```
$ pnpm test
$ pnpm build
$ grep -r SERVICE_ROLE src
$ curl -s -o /dev/null -w "%{http_code}" $BASE_URL/en
```

**앱 주소를 직접 적지 마라.** `$BASE_URL` 을 쓰면 러너가 띄운 앱을 가리킨다.
`http://localhost:3000` 처럼 박아 두면 포트가 바뀔 때 문서를 고쳐야 하고,
더 나쁘게는 **러너가 띄운 앱이 아니라 옆에서 돌던 다른 서버를 검증하게 된다.**
그렇게 나온 통과는 어느 앱의 것인지 알 수 없다.

### HTTP 요청 한 번

```
GET /
GET / [Accept-Language: ko-KR,ko;q=0.9]
POST /api/spots/x/like
```

리다이렉트를 따라가지 않는다. `/a` 가 `/b` 로 갔다가 404 가 되는 흐름이면 **`GET /b` 를 직접 적어라.**

### 화면 조작

```
open /explore
open /explore @375x812
open /explore > click text=Load more > wait 1000
open /explore > fill [data-testid=search] = seoul > press Enter > wait 1500
```

액션은 `>` 로 잇는다. 쓸 수 있는 것:
`click` · `fill 셀렉터 = 값` · `press 키` · `waitFor 셀렉터` · `wait 밀리초` · `goto 경로` · `scroll 픽셀` · `back`

**셀렉터는 사람이 보는 글자로 적어도 된다.** `click text=더보기` 가 그대로 동작한다. `data-testid` 를 붙일 필요가 없다.

### 자동화하지 않기로 정한 것

```
manual: 시각적 인상이라 사람이 봐야 한다
manual: 공급자 하나만 죽은 환경이 필요하다
manual: 실행할 때마다 실제 좋아요 수가 오른다
```

**이유를 반드시 적어라.** 그러면 리포트에 "사람이 볼 것" 으로 이유와 함께 뜬다. 빈 칸으로 두면 "아직 분류하지 않음" 으로 남아 **자동도 수동도 아닌 사각지대**가 된다.

## 4. 판정 칸 — 무엇을 보면 통과인가

```
exit 0                        종료 코드
status 307                    HTTP 상태
-> /en                        이동 위치
stdout empty                  출력이 비었다
stdout has 통과               출력에 이 글자가 있다
body has Nothing matches      본문에 이 글자가 있다
body lacks explore.title      본문에 이 글자가 없다
js location.search.includes("more=1")     화면에서 평가해 참이면 통과
```

여러 개는 `;` 로 잇는다. `status 307 ; -> /ko`

## 5. 자주 걸리는 함정

| 증상                  | 원인                                       | 해법                                                |
| --------------------- | ------------------------------------------ | --------------------------------------------------- |
| 표가 깨진다           | 판정식에 `\|\|` 를 썼다 — 표 구분자와 충돌 | `??` 나 `?.` 로 바꾼다                              |
| 셀렉터 오류           | `[data-x=1]` — 숫자로 시작하는 값          | `[data-x="1"]` 로 따옴표                            |
| 클릭이 시간 초과      | 드롭다운·아코디언이 접혀 있다              | 여는 클릭을 앞에 붙인다                             |
| 화면 글자를 못 찾는다 | 스트리밍이라 첫 응답은 뼈대뿐              | `GET` 대신 `open` + `js ...innerText.includes(...)` |
| 개수가 안 맞는다      | 요청 수와 화면에 그려진 수는 다르다        | 한 번 재보고 하한으로 (`>= 10`)                     |

## 6. 실패가 나오면

**앱을 의심하기 전에 증거를 보라.** `.autoqa/latest.json` 에 상태 코드·본문·평가 결과가 그대로 남는다.

실제 사례에서 나온 실패는 **전부 TC 작성 문제였고 앱 결함은 하나도 없었다.**

- 리다이렉트 후를 봐야 하는데 첫 응답을 봤다
- 화면 문구를 HTTP 응답에서 찾았다 (스트리밍이라 없었다)
- 카드 12개를 기대했는데 11개가 정상이었다 (일부가 걸러진다)
- 스크롤 1000px 를 기대했는데 페이지가 그만큼 길지 않았다

값을 모르겠으면 판정식을 이렇게 바꿔 한 번 재라.

```
js JSON.stringify({ y: window.scrollY, n: document.querySelectorAll('.card').length })
```

증거에 실제 값이 찍힌다. 그 값으로 임계값을 정하면 된다.

## 7. 자동화하지 말아야 할 것

통과 수를 늘리려고 억지로 채우면 **통과의 의미가 얇아진다.**

- **검증이 자기가 재는 숫자를 바꾸는 것** — 좋아요를 누르는 TC 를 자동화하면 그 수는 사용자 반응이 아니라 QA 실행 횟수를 센다
- **타이밍에 걸린 것** — 전환 애니메이션, 낙관적 업데이트 판별. 가끔 실패하는 테스트는 없는 것보다 나쁘다
- **특수 환경이 전제인 것** — "공급자 하나만 죽은 환경", "API 를 502 로 만들 수 있는 환경"
- **외부 자원에 걸린 것** — 외부 CDN 이미지 로드 여부는 그날 네트워크에 달렸다
- **단위 테스트가 이미 덮는 데이터 규칙** — 화면으로는 원인을 가릴 수 없다

이것들은 `manual: 이유` 로 적어라. 자동화 못 하는 것이 아니라 **하지 않기로 정한 것**이고, 그 판단이 문서에 남아야 다음 사람이 다시 고민하지 않는다.

### 자동화 금지 ≠ 확인 금지

**`manual` 로 뺀 TC 를 QA 가 화면에서 직접 확인하는 것은 정상이다.** 위 첫 항목이 특히 헷갈린다 —
좋아요를 누르는 TC 를 자동화하지 않는 이유는 **러너가 매 회차 반복해서** 그 수를 부풀리기
때문이지, 그 동작을 확인하면 안 된다는 뜻이 아니다.

사람이 확인하려면 실제로 눌러야 하고, 그때 데이터가 바뀌는 것은 받아들인 비용이다.
**횟수가 사람의 판단에 묶여 있어서** 자동 반복과 성질이 다르다.

실제로 이 구분이 없어 오해가 났다. QA 가 좋아요 TC 셋을 손으로 확인하고 통과로 찍었는데,
서버 로그에 좋아요 쓰기가 찍힌 것을 보고 "자동화 금지 규칙이 깨졌다" 고 판단한 일이 있었다.
`verdicts.json` 을 열어보고서야 사람이 남긴 것임이 드러났다 — **손으로 찍은 판정에는
`by: "human"` 과 시각이 남으므로 그것으로 가른다.**

## 8. 어디까지 자동화되나

실제 사례(139 TC, 다국어 여행 앱) 기준이다.

```
자동  57건 (41%)   명령 5 · HTTP 12 · 화면 조작 40
수동  나머지        반응 API 12 · 위치 8 · 애니메이션 · 특수 환경
```

**전부 자동화하는 것이 목표가 아니다.** 배포를 막아야 할 P0 가 자동으로 걸리고, 나머지는 왜 사람이 봐야 하는지가 문서에 적혀 있으면 충분하다.
